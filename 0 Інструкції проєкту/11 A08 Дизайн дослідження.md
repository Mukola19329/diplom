# 11 A08 Дизайн дослідження

> **Коли пишеться.** Після Gate здійсненності (**КТ-2**) і **до першого запуску стенда з
> науковою метою**. Технічні прогони «чи взагалі працює» дозволені раніше
> ([[09 Стенд — розгортання]]).
>
> **Що це.** Міст між [[04 ТЗ — Технічне завдання]] («що встановити») і
> [[Журнал дослідження]] («що робив щодня»). Без нього проміжок заповнюється імпровізацією.
>
> **Статус:** `v1.0` → аудит трьома контурами → `v2.0`. Блок 6 (`baseline`) — `Р-N (к)`,
> **КТ-3**.

---

## Блок 1. Вимірювана величина

```
Що міряємо (одним реченням):
Позначення:
Одиниці:
Діапазон можливих значень:
Що означає зростання цієї величини:
```

**Перевірка:** чи можете пояснити цю величину людині, яка не читала вашої роботи, за одне
речення? Якщо ні — вона ще не визначена.

---

## Блок 2. Обʼєкт виміру

```
Дані / симулятор:
Версія, дата отримання:
Походження й ліцензія:
Розмір, структура, розподіл класів:
Контрольна сума:
Чому саме цей обʼєкт (а не інший):
```

> **Останній рядок обовʼязковий.** «Бо він популярний» — не відповідь. Відповідь: «бо він
> містить <властивість>, без якої вимірювана величина не проявляється».

---

## Блок 3. Фактори й рівні

| Фактор | Позначення | Рівні | Крок | Чому такий діапазон |
|---|---|---|---|---|
| | | | | |

**Правило кроку:** діапазон обирається так, щоб **очікуваний ефект був усередині**, а не на
краю. Якщо ефект випадає на межу — ви виміряли фрагмент залежності, а не залежність.

---

## Блок 4. Що тримаємо сталим

| Параметр | Значення | Чому фіксуємо |
|---|---|---|
| | | |

Усе, що не є фактором, мусить бути **явно зафіксоване**. Параметр, який ви не назвали,
змінюється сам.

---

## Блок 5. Повтори і стохастика

```
Кількість повторів (N_REPEATS):
Перелік seed:
Що усереднюємо:
Як показуємо розкид: std / довірчий інтервал / boxplot
Джерела випадковості в стенді (перелічити всі):
```

**Мінімум для бакалавра — 5 повторів.** Одне число без розкиду не є виміром: неможливо
сказати, чи різниця реальна, чи це шум. Технічна реалізація —
[[09 Стенд — розгортання]], §4.3.

---

## Блок 6. Baseline — `Р-N (к)`, КТ-3

```
Baseline (конкретна конфігурація, не назва методу):
Джерело параметрів (№ з Реєстру джерел):
Чому саме цей:
Виміряне значення baseline:
Зафіксовано (дата):
Ратифіковано керівником (дата, Р-N):
```

> **Критерій вибору — не популярність, а режим.**
> Обирайте метод, **міряний у тому самому режимі**, що й ваш вимір. Популярний метод,
> міряний на статичних зрізах, не є baseline для потокового виміру
> (приклад Б у [[07 ПЗ — Процедура закриття]]).

**Після ратифікації baseline не змінюється.** Будь-яка зміна — нове `Р-N (к)` з
переобрахунком **усієї** попередньої серії.

---

## Блок 7. Критерій ефекту

```
Ефект вважаємо наявним, якщо: <кількісна умова>
Обґрунтування порогу:
Як порівнюємо з розкидом:
```

**Заборонено:** «видно на графіку», «помітно краще», «суттєво зростає». Критерій — число,
установлене **до** виміру.

Форма, що працює: *«різниця вважається наявною, якщо перевищує <значення> і виходить за
межі ±1 std обох конфігурацій»*.

## Блок 8. Загрози чинності

Заповніть **усі чотири** типи, навіть якщо десь напишете «не застосовно» — з обґрунтуванням.

### 8.1 Внутрішня чинність — *чи справді причина в тому, що я думаю?*

| Загроза | Чим контролюємо |
|---|---|
| витік даних між навчанням і тестом | |
| зміна кількох факторів одночасно | |
| випадковість видана за ефект | |

### 8.2 Зовнішня чинність — *наскільки результат переноситься?*

| Загроза | Чим контролюємо |
|---|---|
| один набір даних | |
| синтетика замість реальних умов | |
| вузький діапазон факторів | |

### 8.3 Конструктна чинність — *чи міряю я те, що заявляю?*

| Загроза | Чим контролюємо |
|---|---|
| **ціль підмінена проксі** | |
| метрика не відповідає задачі | |

> **Найнебезпечніший із чотирьох типів.** Ви можете бездоганно виміряти **не ту величину**
> і не помітити цього до захисту.
> Питання-тест: *чи є між тим, що я міряю, і тим, що заявляю, хоч один крок припущення?*
> Якщо є — назвіть його явно. Це ж перевіряє крок З-2
> у [[07 ПЗ — Процедура закриття]].

### 8.4 Статистична чинність — *чи витримує різниця перевірку на випадковість?*

| Загроза | Чим контролюємо |
|---|---|
| замало повторів | |
| порівняння середніх без розкиду | |
| множинні порівняння | |

## Блок 9. Що НЕ вимірюємо

```
Поза межами цього дослідження:
Причина відсікання:
Умова повторного відкриття:
```

**Найважливіший блок після восьмого.** Явна межа виміру — головний захист від розповзання.
**Порожній блок 9 означає, що дизайн ще не готовий.**

Сюди ж — контракт розмежування з суміжними темами когорти ([[03 Паспорт напряму]]).
Умови повторного відкриття дублюються в [[OQ — Реєстр відкритих питань]].

---

## Блок 10. Протокол прогону

```
1. Підготовка даних:
2. Навчання / налаштування:
3. Вимір:
4. Збереження результатів (шаблон імені файлу):
5. Обробка й агрегація:
6. Побудова графіка:
```

**Перевірка:** за цим протоколом стороння людина відтворює вимір без вашої участі. Якщо
потрібні усні пояснення — протокол не готовий.

---

## Блок 11. Очікуваний вигляд результату

```
Який графік буде на виході:
Що по осях:
Який вигляд підтвердить гіпотезу:
Який вигляд її спростує:
```

> **Це не передбачення результату, а перевірка дизайну.** Якщо ви не можете намалювати
> порожні осі майбутнього графіка — вимір ще не спроєктований. Малюйте від руки.

Останні два рядки — **заготовка замка**. Перший замок у [[Журнал дослідження]] пишеться
з них.

---

## Блок 12. Ресурсна оцінка

```
Час одного прогону:
Кількість прогонів (фактори × рівні × повтори):
Загальний час обчислень:
Обсяг дискового простору:
Чи вкладається в наявну машину:
```

**Якщо загальний час перевищує 48 годин** — дизайн звужується **зараз**, а не після тижня
очікування. Це `Р-N (к)`.

## Аудит дизайну — три контури перед `v2.0`

| Контур | Питання |
|---|---|
| **Повнота** | чи всі 12 блоків заповнені змістовно, а не формально? |
| **Суперечності** | чи не суперечить критерій ефекту (блок 7) кількості повторів (блок 5)? чи справді величина (блок 1) залежить від факторів (блок 3)? |
| **Сліпі зони** | який параметр змінюється сам, бо я його не назвав? |

Процедура — [[07 ПЗ — Процедура закриття]], крок З-3. Кожна знахідка усунена або
зареєстрована як `OQ-N`.

## Найчастіші дефекти дизайну

| Дефект | Як виглядає | Наслідок |
|---|---|---|
| **Ціль підмінена проксі** | міряємо точність, заявляємо надійність | уся робота про не те |
| **Baseline за популярністю** | «взяв найпоширеніший метод» | немає з чим коректно порівнювати |
| **Немає розкиду** | одне число на конфігурацію | різницю не відрізнити від шуму |
| **Порожній блок 9** | «обмежень немає» | тема розповзається до огляду |
| **Критерій ефекту постфактум** | «різниця виявилася суттєвою» | підгонка, помітна рецензентові |
| **Діапазон на краю** | ефект видно лише в останній точці | виміряно фрагмент |
