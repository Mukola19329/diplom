# 09 Стенд — розгортання

> **Мета.** За один робочий день довести машину до стану, у якому ви можете запустити
> експеримент і отримати графік. Не «вивчити Python», а **мати робочий стенд**.
>
> **Правило першого тижня:** запустіть найпростіший стенд **цього тижня**, навіть на
> синтетичних даних. «Спершу прочитаю все, потім почну» — найпоширеніший спосіб опинитися
> в березні без жодного числа.

---

## 1. Що ставимо

| Інструмент | Навіщо |
|---|---|
| **Python 3.11+** | обчислення, експеримент |
| **VS Code** | редактор, термінал, ноутбуки в одному вікні |
| **Git** | історія коду, відкат, доказ відтворюваності |
| **Obsidian** | волт роботи (уже відкритий) |

Обліковий запис GitHub — бажано, для резервної копії. Робота відкрита, репозиторій може
бути публічним.

## 2. Порядок установлення

### 2.1 Python

З `python.org`, версія 3.11 або новіша.

**Windows:** обовʼязково позначте **«Add Python to PATH»** — найчастіша причина того, що
термінал «не бачить» Python.
**macOS:** системний Python не використовуйте.

```bash
python --version      # Windows
python3 --version     # macOS / Linux
```

### 2.2 VS Code + розширення

**Python** (Microsoft) — обовʼязково · **Jupyter** · **GitLens** · **Ruff**.

### 2.3 Git

```bash
git config --global user.name "Прізвище Імʼя"
git config --global user.email "your@email"
```

## 3. Створення проєкту

```bash
cd <тека вашої теми>/04 Експеримент
mkdir stend && cd stend
git init
```

### 3.1 Віртуальне середовище — обовʼязково

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate
```

Ознака успіху: у терміналі зʼявився `(.venv)`.
У VS Code: `Ctrl+Shift+P` → `Python: Select Interpreter` → оберіть `.venv`.

### 3.2 Бібліотеки

```bash
pip install numpy pandas scikit-learn matplotlib jupyter
pip freeze > requirements.lock.txt
```

`requirements.lock.txt` фіксує **точні** версії. Без нього ваш результат неможливо
відтворити, а невідтворюваний результат не є результатом
([[11 A08 Дизайн дослідження]], блок 5).

## 4. Структура стенда

```
04 Експеримент/stend/
├── README.md              <- як запустити з нуля; пишеться ПЕРШИМ
├── requirements.txt
├── requirements.lock.txt
├── .gitignore
├── config.py              <- усі параметри в одному місці
├── data.py
├── detectors.py
├── metrics.py
├── run_experiment.py      <- точка входу
├── notebooks/             <- розвідка
└── out/                   <- результати
```

### 4.1 `.gitignore`

```
.venv/
__pycache__/
*.pyc
.ipynb_checkpoints/
data/raw/
out/*.png
.DS_Store
```

**Сирі дані в Git не кладуть.** У `data/README.md` — звідки їх узяти й контрольна сума.

### 4.2 `config.py`

```python
SEED = 42
DATA_PATH = "data/raw/dataset.csv"
TEST_SIZE = 0.15
N_REPEATS = 5
OUT_DIR = "out"
```

**Жодного числа посеред коду.** Параметр, розкиданий по трьох файлах, гарантує, що через
місяць ви не знатимете, з чим отримали графік.

### 4.3 Фіксація випадковості

```python
import numpy as np, random
from config import SEED

random.seed(SEED)
np.random.seed(SEED)
# у scikit-learn усюди передавайте random_state=SEED
```

Без цього два запуски дають різні числа, і ви не зможете сказати, чи змінився результат
через вашу правку, чи через випадковість.

## 5. Іменування результатів

```
out/drift_f1__seed42__n5__2026-09-16.png
out/summary__baseline-IF__seed42__2026-09-16.csv
```

Дивлячись на імʼя файлу через три місяці, ви маєте знати, що це.
Файл `результат.png` не є результатом.

## 6. Git — мінімум, якого достатньо

```bash
git add .
git commit -m "стенд: baseline IF, seed 42, F1=0.71"
```

**Коміт після кожного робочого сеансу.** Повідомлення описує **що працює**, а не «зміни».

Раз на тиждень:

```bash
git remote add origin <url>
git push -u origin main
```

**Навіщо це для роботи, а не для коду.** Історія Git — доказ, що результат отриманий тоді,
коли ви кажете. Це та сама функція, що в датованого замка ([[Журнал дослідження]]).

## 7. Мінімальний робочий стенд — перевірте себе

```
[ ] python run_experiment.py запускається з нуля й завершується без помилки
[ ] у out/ зʼявляється щонайменше один графік і один csv
[ ] повторний запуск дає ТІ САМІ числа
[ ] README.md описує запуск так, що стороння людина повторить за 30 хвилин
```

Четвертий пункт — **головний критерій ярусу 1**
([[00 СТАРТ — прочитай першим]], розділ «Що вважається результатом»).
Перевірте буквально: попросіть однокурсника пройти за вашим `README` на його машині.

## 8. Якщо не працює

| Симптом | Причина | Дія |
|---|---|---|
| `python: command not found` | не в `PATH` | перевстановити з позначкою «Add to PATH» |
| `ModuleNotFoundError` | не активоване `.venv` | активувати; `Python: Select Interpreter` |
| Різні числа при повторі | не зафіксовано `seed` | §4.3; перевірити `random_state` у кожній моделі |
| Дані не завантажуються | відносний шлях, запуск із іншої теки | запускати з кореня `stend/`; шляхи через `config.py` |
| Обчислення триває годинами | повний набір замість зрізу | працюйте на зрізі 10 % до налагодження |
| Git просить логін щоразу | не налаштований доступ | створити токен у налаштуваннях GitHub |

**Правило пʼятого дня.** Якщо стенд не запускається **пʼять днів** — сигнал керівникові.
Найчастіша причина — **не ваша некомпетентність, а надто важкий метод або невдалі дані**
для наявної машини. Це рішення класу `Р-N (к)`
([[08 Календар віх і контрольних точок]], §2).

## 9. Що стенд має вміти до КТ-3

```
1. завантажити дані й показати структуру: розміри, класи, пропуски
2. відтворити baseline і вивести його метрику
3. зробити той самий вимір N_REPEATS разів і показати розкид
4. зберегти результат у out/ з іменем, що несе умови
5. побудувати графік, який можна вставити в тезу конференції
```

Це і є **ярус 1** — інструмент. Він не може провалитися: або працює, або ще не дороблений.

---

## 10. Чого не робити

- ❌ ставити бібліотеки без `.venv` — через місяць проєкт не збереться;
- ❌ правити сирі дані: `data/raw/` незмінна, уся підготовка — у коді;
- ❌ тримати числа в ноутбуці: ноутбук для розвідки, результат генерує скрипт;
- ❌ копіювати код, який не розумієте: на захисті спитають, що робить цей рядок;
- ❌ оптимізувати передчасно: спочатку працює, потім швидко.
